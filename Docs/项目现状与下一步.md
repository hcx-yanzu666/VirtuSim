## 已知问题与边界

1. 行人进入路径时，可能出现全局路径变化但机器人停滞；需要结合局部 costmap、cmd_vel 和控制器日志确定原因。
2. 行人仅按距离阈值暂停和恢复，不依靠物理接触阻挡；机器人仍可能与行人重叠或穿过。
3. 机器人移动关闭 Sweep，因此导航 `Succeeded` 不能证明无碰撞。
4. `ScenarioRunner` 在 `BeginPlay` 发出一次目标；没有等待所有外部服务启动并自动重试的完整协调机制。Nav2 / Bridge 未就绪可能导致接收超时或失败。
5. 固定随机种子约束随机采样序列，不保证跨进程异步系统逐帧或逐位确定性。
6. UE 失焦时曾降到约 3 Hz；扫描频率异常时先检查后台限帧。
7. 部署目录地图已更新为当前 UE 关卡导出的候选快照（720 × 560，0.05 m / 格），并非 Blender 原始地图。用户已核对 Ubuntu 复制文件哈希；新地图上的导航仍待验证。
8. 新地图联调时曾发现 `ScenarioRobot_01` 匹配两个 Actor，导致 `ScenarioRunner` 进入 `SetupFailed`，没有应用起点或发送目标。本次关卡变更移除旧方盒机器人；需运行后确认标签仅匹配一个，并核对起点、LiDAR 和静态地图重合。

## 下一步的固定范围

1. 稳定一个行人横穿案例：排查机器人停滞，明确行人接近机器人的行为与评价规则。
2. 统一行人场景的开始、重置和时间基准。
3. 补最小评价指标：实际行驶距离、接触 / 重叠、终态与失败原因。
4. 对基准、噪声、丢点、延迟、行人案例进行少量重复运行，保存汇总、失败日志和演示视频。

先完成这四项，再根据岗位需求决定是否补 Isaac Sim 小案例。相机 / YOLO、多机器人、OpenSCENARIO、自定义 Shader 和 V4 / V5 暂不作为本轮收尾要求。
