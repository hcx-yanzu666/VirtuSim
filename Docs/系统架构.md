# VirtuSim 系统架构

本文描述当前单机器人实现。更长期的扩展见 [演进路线](演进路线.md)，完成情况见 [项目现状](项目现状与下一步.md)。

## 数据流

```text
Config/Scenarios/*.json
          ↓
ScenarioLoader → ScenarioDefinition → ScenarioRunner → Saved/ScenarioResults/*.json
                                            ↓ 起点 / LiDAR 参数 / 导航目标
UE 仓库 + 机器人 + 行人
          ↓ Raycast
LidarComponent → LaserScan → /scan ──────────┐
RobotMotionComponent → /odom、TF ───────────┤
UE /clock ─────────────────────────────────┤
                                           ↓
                                  Ubuntu Nav2 + costmap
                                           ↓ /cmd_vel
                                  RobotMotionComponent
                                           ↓
                                      UE 位姿更新

UE UI / ScenarioRunner → /virtusim/goal_pose → goal_bridge.py → NavigateToPose
UE 取消 → /virtusim/cancel_navigation ──────────────┘
UE 状态 ← /virtusim/navigation_status ← goal_bridge.py ← Action 结果
UE 路径 ← /plan ← Nav2
```

## 模块职责

| 位置 | 职责 |
|---|---|
| `Source/VirtuSim/Communication/` | TempoROS 节点、发布 / 订阅、静态与动态 TF、导航接口 |
| `Source/VirtuSim/Robot/` | 机器人实体、速度积分、LiDAR 扫描、参数、ROS 消息转换 |
| `Source/VirtuSim/Navigation/` | 导航状态、路径数据转换与可视化 |
| `Source/VirtuSim/Scenario/` | JSON 数据定义 / 加载、单轮任务状态机、结果输出、固定路线行人 |
| `Source/VirtuSim/Scene/` | 仓库场景 Actor |
| `Source/VirtuSim/UI/` | 传感器参数与导航交互 |
| `Tools/ROS2/deploy/` | Ubuntu 部署用的 Nav2 参数、地图、Bridge 与诊断节点 |
| `Source/VirtuSim/Scene/NavigationMapExporter.*` | 从当前 UE 关卡静态碰撞体导出 Nav2 地图 |

## 坐标、单位和时间

- UE 世界使用厘米、角度；ROS 使用米、弧度。
- 平移转换：`ROS X = UE X / 100`，`ROS Y = -UE Y / 100`，`ROS Z = UE Z / 100`。
- JSON 起点 / 目标使用 UE 世界坐标，LiDAR 量程和噪声标准差使用米；字段细节见 [场景格式](场景JSON格式.md)。
- `/cmd_vel` 经过 TempoROS 转换后，运动组件使用厘米 / 秒和角度 / 秒；避免再次重复换算。
- ROS 导航节点使用仿真时间；延迟扫描保留采样时间戳，不能改成发送时刻。
- 接收目标 / 等待取消使用墙钟超时，导航运行耗时以接受后的仿真秒计。报告保存 `elapsed_time_basis`。

当前 TF 树及发布责任：

| TF | 当前发布责任 |
|---|---|
| `map → odom` | UE 静态单位变换；当前是真值定位模式 |
| `odom → base_link` | UE 机器人位姿 |
| `base_link → laser_link` | UE 中 LiDAR 安装变换 |

同一条变换只保留一个发布源。以后使用 AMCL 定位时，需要调整 UE 的固定 `map → odom` 发布，不能同时启用两个发布者。

## 场景执行和输出

`ScenarioRunner` 读取 `Config/Scenarios/`，通过 Actor Tag 找到已放置的单个机器人和固定路线行人，应用机器人起点、LiDAR 参数及行人路线，发送导航目标，并监听状态。行人 JSON 只包含 `id`、`actor_tag`、`start`、`end`。当前加载器只支持一个机器人；JSON 配置已有的 Actor 必须在关卡中预先放置，不会自动生成完整关卡资产。

场景行人应用路线后回到起点，暂停移动和动画。Runner 在本轮首次收到 `Navigating` 时同步开始计时并启动这些行人；重复状态通知不会再次启动或重置计时。未由 JSON 配置的行人仍在 BeginPlay 自动往返。

行人行为固定在 C++ 中：速度 100 cm/s，始终沿路线转身，到达端点后立即反向。机器人进入前方 180 cm 范围时暂停，离开 260 cm 范围并保持 0.5 秒后恢复，身后容差为 50 cm。行人开始后不会因为导航任务结束主动停止。

运行生命周期包括初始化、等待接受、导航、等待取消和终态。应用起点后不在 `BeginPlay` 内立刻发目标：先等待本 World 的 odom、动态 TF 和 scan 成功发布，再等待至少 2 秒墙钟时间和仿真时间，给 ROS 发现、时钟回退处理和 Nav2 位姿更新留出时间。预热不计入导航耗时，初始化使用接受等待时限，超时则记录 `SetupFailed`，不发送目标。本地发布成功不是 Nav2 接收确认；异常慢的通信仍需实际联调验证。通信子系统忽略本 World 首次发送目标前的外部导航状态，发目标后 UI 切换到等待接受，并清空缓存路径；接受前合法的失败或取消仍正常处理。当前字符串状态没有运行 ID，仍要求独占单任务。

报告包含场景 / 运行 ID、状态、是否确认任务结束、说明、耗时、目标和 LiDAR 参数。首次 `Navigating` 时开始按机器人 UE 世界位姿累计二维行驶距离，换算成米写入 `travel_distance_meters`；未开始导航的报告省略该字段。接收超时、中断等情况下，需结合 `task_ended_confirmed` 判断外部 Action 是否已结束。

距离按逐帧 XY 位移求和，排除起点初始化瞬移和原地旋转，等待取消确认期间也继续累计，写报告前补采一次。它是采样得到的实际轨迹长度，不是 `/plan` 长度；报告落盘后的移动不计入。

导航开始后，Runner 逐帧用机器人所有静态网格组件在 Actor 局部坐标中的合并包围盒，对照 JSON 配置行人的查询胶囊近似判断几何重叠：XY 平面以机器人包围矩形与胶囊圆形投影相交判定，Z 轴以包围盒和胶囊高度区间相交判定。报告在 `overlap_evaluation_available` 为真时写入 `overlap_episode_count` 和 `overlap_duration_seconds`；episode 表示从无配置行人重叠变为至少一个重叠，持续时间是任一配置行人重叠时间的并集。是否发生过重叠可由 `overlap_episode_count > 0` 直接判断。它按帧采样，使用包围盒而非网格精确表面，不捕获两帧之间的短暂穿越，因此不是物理接触证明，也不改变运动或 Nav2 终态。

- 场景输入：`Config/Scenarios/*.json`，纳入版本管理。
- UE 运行报告：`Saved/ScenarioResults/*.json`，本机输出。
- ROS2 诊断：默认 `/home/ros2/virtusim_nav2/logs/navigation_diagnostics.jsonl`，可用 `--output` 为每次实验指定独立文件。
- 地图导出工具：`Source/VirtuSim/Scene/NavigationMapExporter.*`，使用说明见 [UE 场景地图导出](UE场景地图导出.md)。
- 待部署地图：`Tools/ROS2/deploy/warehouse_map.pgm` 与同目录 YAML；从当前 UE 关卡重新导出后再部署。

## 当前建模精度

机器人使用 Mesh 组装、运动学积分和真值里程计。行人使用胶囊作为 LiDAR 查询代理，骨骼网格负责外观和动画。机器人移动关闭 Sweep，行人也没有接触动力学或自主避让。

这些实现用于导航通信、传感器退化和场景执行验证；完整动力学、接触验证、真实数据重建和 Sim2Real 不属于已完成能力。
