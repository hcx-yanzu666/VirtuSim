# VirtuSim 系统架构

本文描述当前单机器人实现。更长期的扩展见 [演进路线](演进路线.md)，完成情况见 [项目现状](项目现状与下一步.md)。

## 数据流

```text
Config/Scenarios/*.json
          ↓
ScenarioLoader → ScenarioDefinition → ScenarioRunner → Saved/ScenarioResults/*.json
                                            ↓ 起点 / LiDAR 参数 / 导航目标
UE 仓库 + 机器人 + 行人
          ↓ Raycast
LidarComponent → LaserScan → /scan ──────────┐
RobotMotionComponent → /odom、TF ───────────┤
UE /clock ─────────────────────────────────┤
                                           ↓
                                  Ubuntu Nav2 + costmap
                                           ↓ /cmd_vel
                                  RobotMotionComponent
                                           ↓
                                      UE 位姿更新

UE UI / ScenarioRunner → /virtusim/goal_pose → goal_bridge.py → NavigateToPose
UE 取消 → /virtusim/cancel_navigation ──────────────┘
UE 状态 ← /virtusim/navigation_status ← goal_bridge.py ← Action 结果
UE 路径 ← /plan ← Nav2
```

## 模块职责

| 位置 | 职责 |
|---|---|
| `Source/VirtuSim/Communication/` | TempoROS 节点、发布 / 订阅、静态与动态 TF、导航接口 |
| `Source/VirtuSim/Robot/` | 机器人实体、速度积分、LiDAR 扫描、参数、ROS 消息转换 |
| `Source/VirtuSim/Navigation/` | 导航状态、路径数据转换与可视化 |
| `Source/VirtuSim/Scenario/` | JSON 数据定义 / 加载、单轮任务状态机、结果输出、固定路线行人 |
| `Source/VirtuSim/Scene/` | 仓库场景 Actor |
| `Source/VirtuSim/UI/` | 传感器参数与导航交互 |
| `Tools/ROS2/scripts/` | Nav2 Action Bridge 与诊断节点 |
| `Tools/WarehouseGenerator/` | 仓库模型、地图生成和编辑器导入工具 |

## 坐标、单位和时间

- UE 世界使用厘米、角度；ROS 使用米、弧度。
- 平移转换：`ROS X = UE X / 100`，`ROS Y = -UE Y / 100`，`ROS Z = UE Z / 100`。
- JSON 起点 / 目标使用 UE 世界坐标，LiDAR 量程和噪声标准差使用米；字段细节见 [场景格式](场景JSON格式.md)。
- `/cmd_vel` 经过 TempoROS 转换后，运动组件使用厘米 / 秒和角度 / 秒；避免再次重复换算。
- ROS 导航节点使用仿真时间；延迟扫描保留采样时间戳，不能改成发送时刻。
- 接收目标 / 等待取消使用墙钟超时，导航运行耗时以接受后的仿真秒计。报告保存 `elapsed_time_basis`。

当前 TF 树及发布责任：

| TF | 当前发布责任 |
|---|---|
| `map → odom` | UE 静态单位变换；当前是真值定位模式 |
| `odom → base_link` | UE 机器人位姿 |
| `base_link → laser_link` | UE 中 LiDAR 安装变换 |

同一条变换只保留一个发布源。以后使用 AMCL 定位时，需要调整 UE 的固定 `map → odom` 发布，不能同时启用两个发布者。

## 场景执行和输出

`ScenarioRunner` 读取 `Config/Scenarios/`，通过 Actor Tag 找到已放置的单个机器人，应用起点和 LiDAR 参数，发送导航目标，并监听状态。当前加载器只支持一个机器人，不会根据 JSON 自动生成完整关卡或配置行人。

运行生命周期包括初始化、等待接受、导航、等待取消和终态。报告包含场景 / 运行 ID、状态、是否确认任务结束、说明、耗时、目标和 LiDAR 参数。接收超时、中断等情况下，需结合 `task_ended_confirmed` 判断外部 Action 是否已结束。

- 场景输入：`Config/Scenarios/*.json`，纳入版本管理。
- UE 运行报告：`Saved/ScenarioResults/*.json`，本机输出。
- ROS2 诊断：默认 `/home/ros2/virtusim_nav2/logs/navigation_diagnostics.jsonl`，可用 `--output` 为每次实验指定独立文件。
- 生成候选地图：`Tools/WarehouseGenerator/Output/ROS2/`。
- 待部署地图快照：`Tools/ROS2/maps/`；确认与关卡一致后再部署。

## 当前建模精度

机器人使用 Mesh 组装、运动学积分和真值里程计。行人使用胶囊作为 LiDAR 查询代理，骨骼网格负责外观和动画。机器人移动关闭 Sweep，行人也没有接触动力学或自主避让。

这些实现用于导航通信、传感器退化和场景执行验证；完整动力学、接触验证、真实数据重建和 Sim2Real 不属于已完成能力。
